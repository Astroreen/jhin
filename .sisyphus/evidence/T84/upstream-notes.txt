Plan-vs-upstream discrepancies (do not trust plan prose; measured):
1. Plan T84/T83 prose says "47 semantic names"; the real surface is 56
   (UiTokens.COLOR_KEYS; upstream index.css:221-276 has 56 --color-*
   aliases; confirmed in T83 evidence). PaletteGen emits exactly the
   UiTokens.COLOR_KEYS set.
2. Plan T84 step 2 "each foreground binary-searched to >= 7:1 against its
   own surface" is not the upstream contract. themePalette.ts:705 solves
   the text to 7:1 on the canvas; :739-742 solves the surface foregrounds
   to 4.6:1; :813-824 picks fixed candidates at a 4.5 floor; :743-744 and
   :856-869 blend muted text to 4.6 / 4.705 / 5.082. The 7:1 target is in
   fact unreachable on mid-tone canvases: max-chroma magenta canvas tops
   out at 6.70:1 and mid-grey at 5.32:1 (black text), and the upstream
   solve then returns the extreme reachable colour. Ported with upstream's
   targets; PaletteGenTest asserts the strict suite on the five built-in
   pairs and the documented weaker floor on the adversarial pairs
   (measured adversarial minima: message-foreground 3.50,
   update-foreground 3.66, accent-foreground 3.83, placeholder 4.31 on
   mid-grey #808080).
3. Plan/task prose "error/warning blends (8% dark / 16% light)" is inverted.
   Upstream mixes 0.16 for dark canvases and 0.08 for light ones
   (themePalette.ts:638-641; index.css:1098 light 8%, :1153 dark 16%).
   Ported upstream's order.
4. Plan acceptance "the generated colour maps match the explicit OKLCH maps
   in packages/shared/src/themePalettes.ts within dE < 2" holds only for the
   seed-determined roles. The five built-ins are hand-tuned art: their
   surfaces and foregrounds carry their own hues (t3-chat light text
   oklch(0.325698 0.116116 325.037) at themePalettes.ts:261 vs the
   generator's accent-hue whisper at themePalette.ts:697-701) and their
   companion actions are not the +50 rotation. Measured dE76 (true CIELAB)
   of generated vs explicit, max over 5 built-ins x light+dark:
     canvas/chrome/toolbar/terminalBackground      0.43
     accent/focus/update/terminalCursor            0.49
     warningSurface                                1.91
     warningForeground                             6.60
     warning                                       6.08
     errorSurface                                  8.21
     codeBackground                                9.45
     surface                                      10.97
     ... (ladder and foreground roles) up to
     messageAction                                86.11
   PaletteGenTest therefore asserts dE76 < 2 on the seed-determined roles
   (background/ring/update vs the explicit canvas/accent values, measured
   0.000-0.491 — see deltaE.txt) and reports the rest here rather than
   asserting a false bound.
5. Plan T84 step 3 lists "terminal-*" among the emitted families; there is
   no --color-terminal-* alias (index.css:221-276) and no terminal key in
   UiTokens.COLOR_KEYS. The generator emits exactly the 56 COLOR_KEYS
   names per the task brief; upstream's terminal-* remain plain CSS
   variables outside the color token family.
6. The task brief's "5 built-in seed pairs" are the light palettes'
   (canvas, accent) of the five built-ins (all declare appearance "light":
   themePalettes.ts:254, :381, :508, :635, :762); the four adversarial
   pairs are near-black #050505 + grey #808080, white + white,
   max-chroma magenta #ff00ff + #ff00ff, mid-grey + mid-grey.
7. Output format: upstream returns oklch(...) strings
   (formatOklchThemeColor themePalette.ts:391-399); the Jhin ports return
   8-bit hex as the task brief requires ("byte-identical hex output"). The
   mixes keep fractional channels upstream (:470-479) and only hex
   formatting rounds (:425-433) — the ports mirror that.
8. Seed alpha: upstream parseThemeRgbColor (:420-423) drops the alpha of
   #AARRGGBB seeds; the ports accept #RRGGBB and #AARRGGBB and ignore the
   alpha byte the same way. Anything else raises the typed PaletteError
   (stricter than upstream's silent fallback — the task brief requires the
   typed error).
9. Appearance argument: upstream ThemeAppearance is light|dark and is used
   only for the parse-fallback colours (:674-677) — every ramp and contrast
   search keys off the canvas (:682-686). The ports add "system", resolved
   off the canvas luminance, and use the slot only for the light-dark()
   fixed tokens (info/success/diff foregrounds, index.css:2027-2028).
10. Files deviation (task brief vs plan Files): the QA happy path required
    "save-appearance with canvas/accent seeds -> bootstrap tokens reflect
    generated palette", so plugins/ui-default/.../BootstrapRoute.java was
    wired: theme.colors now carries PaletteGen.generate(appearance, canvas,
    accent) instead of the four static example colours (docs/sdui.md
    section 1: colors overrides win over client generation, so a full
    generated map pins the server palette). BootstrapContractTest stays
    green (it asserts the theme key set, not the map contents). One client
    line followed from the same requirement: frontend/lib/design/theme.dart
    _applyOverrides now prefers the token-named pair (primary,
    primary-foreground) over the brand-seed spelling (accent, onAccent)
    when both are present, because the generated map uses the
    UiTokens.COLOR_KEYS names where --primary is the companion message
    action (index.css:1246-1247) and --color-accent is the accent surface
    (index.css:255 -> :1255). Both spellings keep working; the existing
    theme_test.dart contract (colors{accent} -> scheme.primary) is
    unchanged and green.
11. Plan §15.2 (OKLCH rounding parity) answered: byte-exact, no dE<0.5
    fallback needed. The two ports share a deterministic float core —
    fixed-iteration ln/exp/cbrt/sin/cos/atan2 series, x*x*x cubes,
    IEEE-exact sqrt, floor(x+0.5) rounding, the gamut step count by exact
    halving, and a truncated-mod hue wrap (Dart's % is Euclidean where
    Java's is truncated) — so no libm or pow/cbrt/atan2 disagreement is
    possible. Proven by the goldens in frontend/test/design/
    t84_golden_data.dart (Java-produced) and by the QA dump diff.
12. Toolchain note: the research tooling redacted long decimal literals in
    transit (phone-number false positive) — e.g. the OKLab matrix constants
    of themePalette.ts:504-531 render as placeholders in tool output. The
    values on disk are the standard published OKLab matrices; behaviour is
    verified end to end (upstream invariant suite green, seed round-trips
    exact, 8/9 Tailwind hexes byte-equal to the published v4 values).
