T202 browser step: UNAVAILABLE in this environment.

Why: the executing agent has no browser tools — no browser navigate, no
screenshot, no ARIA snapshot, no evaluate. The available tools are a shell,
file read/write/edit, grep/glob and a URL-to-markdown fetcher (webfetch);
none of them can drive a live DOM, take a screenshot or produce an ARIA
snapshot of the booted server. Nothing is fabricated: no snapshot.yaml and
no screen.png are produced.

Per plan section 9 (browser unavailability may be reported), the curl-level
snapshot substitute ran instead — see snapshot-substitute.txt and
shell-root.txt:
  - the served shell.html parses as an HTML document (doctype) with the
    #jhin-root element present and its region non-empty (shell-root.txt);
  - the app title <title>Jhin</title> is in the document;
  - the inlined runtime that fills #jhin-root (getElementById("jhin-root"))
    is present in the served document;
  - the served screens/fallbacks html carries at least one <button>.

Browser-step failure cases:
  - text/plain content type -> COVERED by the curl asserts (the shell is
    asserted text/html; a text/plain answer fails the run);
  - api=4 payload without html -> COVERED by the curl asserts (screens[0].html
    and both fallbacks must be html fragments; a node-only payload fails);
  - snapshot with an empty #jhin-root -> NOT verifiable without a browser.
    The static shell document intentionally ships the empty root element;
    app.js populates it from the bootstrap payload at load time, and that
    runtime DOM fill cannot be observed over curl. Recorded here as
    unproven, not fabricated.

The ARIA snapshot (snapshot.yaml) and the screenshot (screen.png) remain the
only missing artifacts of this chunk; every other T202 assertion is proven
by scripts/qa/t202.sh (see summary.txt).
