Value-shape rule (applied uniformly, matches the QA pins):
- rem / % / s values and composite CSS values (rgb(), calc(),
  cubic-bezier(), shadow stacks) are verbatim strings;
- plain px lengths and unitless numbers are numbers (px loses its unit —
  this is what pins layout.topbarHeight == 52 and motion.panel == 0);
- theme-dependent values are {light, dark} maps, the responsive gutter is a
  {base, sm} map; JhinTheme.resolve collapses both.

Plan discrepancies found against the checkout (plan prose vs upstream):
1. Colour count: the plan says "47 semantic names"; the @theme inline
   --color-* alias list carries 57 entries — 56 semantic names (verbatim,
   implemented) plus the raw palette constant zinc-25 (excluded: not a
   semantic name). No principled 47-name subset exists, so the verbatim
   alias list is the implemented key set (UiTokens.COLOR_KEYS).
2. Font-size clamps: the plan says "clamps 12-18 / 12-18 / 12-20" for
   sizeInterface/sizePrompt/sizeCode; upstream is
   packages/contracts/src/settings.ts:122-139 — interface 12-20 (default 16),
   prompt 12-20 (default 14), code 10-18 (default 13). The token values are
   the upstream defaults (16/14/13); the clamp bounds matter for T86 and are
   recorded here so T86 does not inherit the plan's ranges.
3. color values "each either raw or --contrast-*": the alias targets are
   mostly plain var(--x) indirections (the "raw" case), with 15 pointing at
   var(--contrast-x); values are the verbatim alias targets either way.
4. space.control: upstream has no --control-inset; the only `control`
   geometry value is --control-radius: 0.5rem (index.css:101), which is the
   value the plan quotes ("control 0.5rem"). Implemented from that anchor.
