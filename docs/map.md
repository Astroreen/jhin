# Map of Jhin

Everything Jhin already has, one line each: an inch deep, a mile wide. Read
it before building anything, so you extend what exists instead of building it
again next to it ([reinvent the wheel](lore/reinvent-the-wheel.md)). Each
line routes to the place that knows the details; open that only when you need
it.

The live truth of a running node is `jhin inspect` (plugins, services,
hooks, slots, mesh) and `jhin host.commands.list`. This map is the
territory's outline; when they disagree, fix the map.

When you add a package, plugin, capability or command, add its line here in
the same PR.

## Shape

- **Kernel** (`packages/kernel`): plugins, capabilities, services, hooks,
  commands, config layers, events, disposables, scoped state. Isomorphic, no
  product in it. → `plans/foundation.md#kernel-and-plugins`
- **Node** = a host (`packages/node-host`) running server plugins; **client**
  = the web app (`apps/web`) running a second kernel with client plugins.
  → `plans/foundation.md#mesh-nodes-transport`
- Every operation is a **command**, reachable as an RPC method, a CLI
  subcommand (`jhin <command>`) and an MCP tool. → `AGENTS.md` rule 6
- UI is **slots** and **contributions** with stable ids. → `plans/t3-parity.md#ui`
- A command or stream names **permissions**; a caller holds **grants**
  (`git.read`, `git.*`, `*`) checked by `holdsPermission` in `@jhin/sdk`.
  Remote callers hold the grants of their token; mesh calls carry their
  caller's. → `plans/security.md#permissions-and-scoped-tokens`

`host.config.get`, `host.config.patch`, `host.config.edit` (leaf paths, D476),
`host.config.schema`, `host.config.secrets.migrate` (config secrets into the

The builtin `jhin.host-secrets` resolves config secret references through
`secrets.store@1` when it is active (D1025).
The builtin `jhin.host-streams` serves the live streams `host/config`
(`host.config.changed`, `plans/config-ui.md` D483) and `host/device-settings`
(`host.device-settings.get`/`.patch`, D487).

age (`configEdits`, `configChange`; `plans/config-ui.md` D475).
A config field asks for a control a plugin contributes with
`.meta({ control })`: the slot `settings.config.control.<name>`
(`configControlSlot`, `ConfigControlProps` in `@jhin/client-api`; `Slot`'s
`first` and `useOptionalSlot` in `@jhin/ui`; `plans/config-ui.md` D482).

## Apps, tests, scripts

- `apps/jhin` — the CLI `jhin` (published as `jhin-ai`): `serve`, `inspect`,
  and every command as a subcommand.
- `apps/web` — the web client.
- `apps/desktop` — the Electron desktop app: runs `jhin serve --ui` and shows
  the web client (`plans/desktop.md`).
- `packages/desktop-api` — the desktop bridge's contract (`window.jhinDesktop`,
  update state, `desktop.shell@1`), with its channel names apart for the
  preload (`plans/desktop.md#D521`).
- `jhin serve --plugin-dir <dir>` — loads a plugin package from outside the
  plugin folders, as the dev layer (D15); the desktop app adds its plugin so.
- `agent.runtime` 1.5 (`@jhin/agent-api`): a question's `initialAnswer`, an
  answer to edit (`plans/t3-parity.md` D1001).
- `@jhin/agent-api`'s `citations.ts` — a quote of an agent's message in a user's
  (`jhin-citation://`), and what the agent reads of it (`plans/t3-parity.md`
  D1010).
- `chat.composer.insert-context` (the chat plugin) — puts a context record and its
  chip into the open composer; the terminal's "Add to chat" uses it
  (`plans/t3-parity.md` D1009).
- `@jhin/agent-api`'s message context records (`context.ts`): `jhin-context://`
  references, `projectMessageContext` (what an agent reads of a message with
  records), the records `threads.send` and the queue take
  (`plans/t3-parity.md` D1006).
- `projects.read-file` and `agents.skill.read` (`jhin.threads`) — the start of
