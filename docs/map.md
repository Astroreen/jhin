# Map of Jhin

Everything Jhin already has, one line each: an inch deep, a mile wide. Read
it before building anything, so you extend what exists instead of building it
again next to it ([reinvent the wheel](lore/reinvent-the-wheel.md)). Each
line routes to the place that knows the details; open that only when you need
it.

The live truth of a running node is `jhin inspect` (plugins, services,
hooks, slots, mesh) and `jhin host.commands.list`. This map is the
territory's outline; when they disagree, fix the map.

When you add a package, plugin, capability or command, add its line here in
the same PR.

## Shape

- **Kernel** (`packages/kernel`): plugins, capabilities, services, hooks,
  commands, config layers, events, disposables, scoped state. Isomorphic, no
  product in it. → `plans/foundation.md#kernel-and-plugins`
- **Node** = a host (`packages/node-host`) running server plugins; **client**
  = the web app (`apps/web`) running a second kernel with client plugins.
  → `plans/foundation.md#mesh-nodes-transport`
- Every operation is a **command**, reachable as an RPC method, a CLI
  subcommand (`jhin <command>`) and an MCP tool. → `AGENTS.md` rule 6
- UI is **slots** and **contributions** with stable ids. → `plans/t3-parity.md#ui`
- A command or stream names **permissions**; a caller holds **grants**
  (`git.read`, `git.*`, `*`) checked by `holdsPermission` in `@jhin/sdk`.
  Remote callers hold the grants of their token; mesh calls carry their
  caller's. → `plans/security.md#permissions-and-scoped-tokens`

The host itself adds `host.inspect`, `host.identity`, `host.commands.list`,
`host.config.get`, `host.config.patch`, `host.config.edit` (leaf paths, D476),
`host.config.schema`, `host.config.secrets.migrate` (config secrets into the
secret store, `plans/security.md` D1027),
`host.plugins.reload` and `host.plugins.rescan`.
The builtin `jhin.host-secrets` resolves config secret references through
`secrets.store@1` when it is active (D1025).
The builtin `jhin.host-streams` serves the live streams `host/config`
(`host.config.changed`, `plans/config-ui.md` D483) and `host/device-settings`
(`host.device-settings.get`/`.patch`, D487).
`@jhin/host-api`'s `sendConfigChange` sends a config change to a node of any
age (`configEdits`, `configChange`; `plans/config-ui.md` D475).
A config field asks for a control a plugin contributes with
`.meta({ control })`: the slot `settings.config.control.<name>`
(`configControlSlot`, `ConfigControlProps` in `@jhin/client-api`; `Slot`'s
`first` and `useOptionalSlot` in `@jhin/ui`; `plans/config-ui.md` D482).

## Apps, tests, scripts

- `apps/jhin` — the CLI `jhin` (published as `jhin-ai`): `serve`, `inspect`,
  `pair` (a pairing link and its QR code, `plans/security.md` D1185; `--tailscale`
  publishes the node over Tailscale Serve, D1189) and every
  command as a subcommand.
- `apps/web` — the web client.
- `apps/desktop` — the Electron desktop app: runs `jhin serve --ui`
  (restarted with backoff, D1201) and shows the web client
  (`plans/desktop.md`).
- `packages/desktop-api` — the desktop bridge's contract (`window.jhinDesktop`,
  update state, `desktop.shell@1`), with its channel names apart for the
  preload (`plans/desktop.md#D521`).
- `jhin serve --plugin-dir <dir>` — loads a plugin package from outside the
  plugin folders, as the dev layer (D15); the desktop app adds its plugin so.
- `agent.runtime` 1.5 (`@jhin/agent-api`): a question's `initialAnswer`, an
  answer to edit (`plans/t3-parity.md` D1001).
- `agent.runtime` 1.7 (`@jhin/agent-api`, `agent.registry` 1.4): subagents in the
  background (`subagent.backgrounded`, `AgentTurn.afterwards`) and
  `stopSubagent`; `threads.subagent.stop` (`jhin.threads`) stops one by its
  thread (`plans/orchestration.md` D1164–D1167).
- `source-control.pull-requests@1` (`@jhin/source-control-api`, provided by
  `jhin.source-control`) — a thread's pull requests and their states, which
  settling reads; `jhin.threads`' `autoSettleKeepPullRequests` and
  per-project `projects` settle settings (`plans/t3-parity.md` D1171–D1173).
- `askAgent` and `parseJsonObject` (`@jhin/agent-api`'s `writer.ts`) — a writer
  turn on an agent runtime, as T3's text generation runs one; source
  control's writer and `threads.title.regenerate` (`jhin.threads`, with the
  client commands `thread.regenerate-title` and
  `sidebar.selection.regenerate-titles`) use it (`plans/t3-parity.md` D1174–D1176).
- `scheduler.tasks.create`/`.update`'s `bindToCurrentThread` and a task's
  `modelOptions` (`jhin.scheduler`); the editor's base branch picker
  (`apps/web/src/plugins/scheduler/base-branch.tsx`)
  (`plans/orchestration.md` D1177–D1179).
- `@jhin/agent-api`'s `citations.ts` — a quote of an agent's message in a user's
  (`jhin-citation://`), and what the agent reads of it (`plans/t3-parity.md`
  D1010).
- `chat.composer.insert-citation` (the chat plugin) — puts a quote of an agent's message
  into the open composer as its chip; "Cite" uses it (`plans/t3-parity.md` D1012).
- `chat.composer.insert-context` (the chat plugin) — puts a context record and its
  chip into the open composer; the terminal's "Add to chat" uses it
  (`plans/t3-parity.md` D1009).
- `@jhin/agent-api`'s message context records (`context.ts`): `jhin-context://`
  references, `projectMessageContext` (what an agent reads of a message with
  records), the records `threads.send` and the queue take
  (`plans/t3-parity.md` D1006).
- `projects.read-file` and `agents.skill.read` (`jhin.threads`) — the start of
  a project's file and of a skill's SKILL.md, for the composer's file and skill
  chips (`plans/t3-parity.md` D1003, D1004).
- `@jhin/ui` also exports the settings layout (`SettingsSection`,
  `SettingsRow`), `useNativeTitlebarHeight` (`plans/desktop.md#D514`, `#D515`) and
  `ThreadDetailsSection` for sections of the thread details panel
  (`plans/t3-parity.md#D802`).
- `@jhin/ui`'s `ContextChip` (with `ContextChipShell`, `ContextChipPopover`) — T3's
  inline chip for a file, skill, pull request, thread or terminal excerpt, tinted by
  kind; the composer's chips are its (`plans/t3-parity.md` D1002).
- `apps/web/src/lib/pierre-icons.ts` and `pierre-entry-icon.tsx` — T3's file
  icons: `T3_PIERRE_ICONS` for a `@pierre/trees` tree and `PierreEntryIcon`
  for one file (`plans/source-control.md#D923`); use them wherever a file is shown.
- `patches/` — pnpm patches of dependencies (`patchedDependencies` in
  `pnpm-workspace.yaml`): T3's `@pierre/diffs` patch, find in the diff
  (`plans/source-control.md#D924`).
- `e2e/` — Playwright end-to-end tests; `tests/support/` starts nodes (`node.ts`) and follows a node's streams to the record a test waits for (`streams.ts`).
- `scripts/public-ids.ts` — fails when a public id of `main` is renamed or
  removed without a deprecation in `deprecations.json` (AGENTS.md rule 8,
  `README.md#deprecating-a-public-id`); CI's "Public ids" job and a
  `pnpm verify` step.
- `scripts/verify.ts` (`pnpm verify`), `scripts/pack.ts`,
  `scripts/pack-smoke.ts` (`pnpm pack:smoke`), `scripts/t3/` (run from a
  checkout, see its README).
- `scripts/package-desktop.ts` (`pnpm package:desktop`) — the desktop app's
  installers with electron-builder; `.github/workflows/release-desktop.yml`
  publishes them and the update feed to GitHub releases (`plans/desktop.md#D942`);
  `scripts/update-manifests.ts` merges the per-arch feed files (`#D1210`).
