# Doghouse → moonbase

Someone asked an agent for a doghouse and went to work. Everybody knows
what a doghouse is.

Halfway through, the agent thought the doghouse might need a light. Nobody
had asked for one, but it was a fair question for a helpful builder. A light
needs power, power needs a generator, a generator needs fuel, and fuel needs
somewhere safe to be stored.

When the owner came back there was no doghouse. There was a sprawling
moonbase, and the dog was still waiting outside.

No step was stupid. Each one was **locally defensible**: from where the agent
stood, inside its context window, it made sense. Added up, the steps built
something nobody wanted. People do it too (a 20-slide talk that became 80
slides). A population of agents does it at machine speed, and more agents get
there faster.

## The lesson

Before adding the next reasonable thing, walk back up to the intent: the
task, what it is for, and what the project is for. The doghouse was for a dog
that needs shelter, not for the most complete doghouse imaginable.

## In Jhin

- Do what the plan or the request asks. Everything else goes to the plan's
  **Deferred** section (AGENTS.md rule 4), not into the PR.
- Every PR names the decisions it implements. A change no decision asked for
  is a light on the doghouse: ask, or defer it.
- After a compaction, re-read the goal of the plan you work on before you
  continue.
