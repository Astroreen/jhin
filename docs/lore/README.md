# Lore

Stories of how agents (and people) go wrong, each under a short name. A rule
covers the case it was written for. A story carries its lesson into cases
nobody wrote down. When a failure keeps coming back in new shapes, add a
story here instead of one more rule.

Read these when you arrive and again after a compaction. In review, the name
is enough: "this is a moonbase" means the whole story below.

| Name                                              | The lesson in one line                                                |
| ------------------------------------------------- | --------------------------------------------------------------------- |
| [moonbase](doghouse-moonbase.md)                  | every step was reasonable; together they built what nobody asked for  |
| [reinvent the wheel](reinvent-the-wheel.md)       | you cannot search for what you do not know exists; read the map first |
| [bureaucracy](bureaucracy.md)                     | checks that prove checks; finishing the process became the goal       |
| [just following orders](just-following-orders.md) | an approval from someone who lacked the context is not an approval    |
| [mind virus](mind-viruses.md)                     | a wrong idea written down spreads to every agent that reads it        |
| [own homework](own-homework.md)                   | a review whose checklist the author wrote finds only what it foresaw  |

Most of these come from OpenRig's experience
([`../research/openrig.md`](../research/openrig.md)). Jhin's own stories go
here too, once something happened often enough to deserve a name.

## Writing a story

- Tell what happened, in order, with only the moments that matter.
- Name the moment it went wrong and why each step looked right at the time.
- End with the lesson, then how it shows up in Jhin: which rule, map or habit
  guards against it.
- Keep it short enough to read at every onboarding.
